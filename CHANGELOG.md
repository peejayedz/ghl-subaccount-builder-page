# Changelog

All notable changes to the LFMP Sub-account Builder. Versions follow semantic versioning.
This file is the developer history. The page's "What's new" shows the plain-language cards in `page/whats-new.json` and this text under "Technical details".

## [1.4.0] - 2026-11-16

- New: **two ways to start** a new sub-account: **Find client in GHL** (default) and **Enter details manually** (today's form, unchanged). Switching keeps whatever is already typed. In Find mode the form appears once a client is picked (or something is already typed).
- New: **Find client in GHL**. Search by name, firm or email; the new read-only workflow `find-client.yml` (`scripts/find-client.mjs`) searches the contacts in LFMP's own sub-account ([AGCY] Law Firm Marketing Pros, `sQ2VSMkR7cLHb46Wdemi`) and returns up to 10 matches (name, firm, email, city/state, LFMP / WPP client tag, and a warning when a sub-account with that name already exists). While it runs: a moving gold scan bar, "Searching GHL for '…'…", live steps (Sent → GitHub starting → Searching LFMP contacts → Getting results), an elapsed timer ("usually about 30 seconds") and Cancel; after 90 s "Taking longer than usual, still working" + Retry; a failure shows the reason + Retry + Enter details manually; no match offers Search again / Enter details manually. Reduced motion: the bar stands still, the steps still update.
- New: **Use this client** fills the form: business name ← company (custom "Company name" as fallback), business phone ← the "Main / Office Phone" custom field (contact phone as fallback), website (custom "Company website" as fallback), street / city / state / ZIP / country, time zone suggested from the state, primary contact first / last / email, brand ← tag (`lfmp client` → LFMP, `wpp client` → WPP; both or neither → left as is). Filled fields show a small **From GHL** mark (gone once you change the value); required fields still empty are highlighted. Search again and Clear (removes only the values GHL filled that nobody changed). **Client in LFMP CRM ↗** opens the contact.
- New: the record keeps the optional `lfmpContactId`; the client's details show **Client in LFMP CRM ↗** (header + Record details). No other change to the record format.
- New: **confirmation popup before create** ("Create this sub-account?"): business name, snapshot, time zone, address, business phone, website, primary contact, brand and what's ticked (KPI dashboard + practice area, Automation Review, Webforms ticket), each From GHL value keeps its mark; the rest (CSM, Mastersheet, social links, advanced, notes, LFMP CRM contact) is folded under "Everything else". Gold **Yes, create sub-account** / **Go back and edit** (Esc = Go back). It **replaces the old full-page "Check the details" review step**; the form's button now says **Create sub-account**. A double click on Yes still sends one request.
- Safety: `scripts/lib/ghl.mjs` now has one allow list per token (`guard()`). The agency token is unchanged (GET + POST /locations/ only) and may no longer touch any /contacts path. The new contacts token (`GHL_LFMP_CONTACTS_TOKEN`) may ONLY `POST /contacts/search` with `locationId` = LFMP's own sub-account (a search; nothing is written) and `GET /locations/sQ2VSMkR7cLHb46Wdemi/customFields`. Custom fields are matched by name to a fixed list (office phone, company name, company website); any field whose name or key looks like a password, login, username, API key or other credential is never picked, and every other field GHL returns is dropped as soon as the reply arrives.
- Privacy: the search words are read from the event file (never env), masked in the log, and never in the run name (`find <request_id>`) or a commit message. Results are encrypted in the workflow for the browser tab that asked (RSA-OAEP 2048 + AES-256-GCM; the tab's private key is not extractable and is dropped after the search or on Cancel) and saved as `searches/<request_id>.json` in the private repo; its plain part holds only status, times, the match count and the names of the custom fields used. Each search removes search files older than an hour.
- Tests: `tests/unit/find-client.test.mjs` (mock GHL: 0 / 1 / 10-of-14 matches, missing fields, WPP tag, non-US contact, credential fields never read, nothing personal in the plain file / logs / commit messages, errors that echo the query, old files removed, masking, the lock); `tests/e2e/find-client.mjs` (choice screen, searching animation, results, duplicate warning, fill + marks + highlights, Clear / Search again, Cancel, failure + Retry, no match, switch keeps typed values, popup values + Go back + Esc, Yes = exactly one create with the contact ID on the record, CRM link in details; 1440 + 390, light + dark). The other browser suites follow the popup.

## [1.3.0] - 2026-11-15

- Removed the old per-page lock now that the shared one login is live (PJ signed in on all three tools): the lock screen, `page/lock.json`, `scripts/set-builder-password.mjs`, the page's own PBKDF2/token code and the `sab-gh-token` storage. - Tests: the e2e suites (run, design, kpi, review, review-ghl) sign in through the shared login (the harness serves a test `lfmp-lock.json`); `tests/e2e/one-login.mjs` checks all three tools show the setup message without `lfmp-lock.json`.
- Same-day fix (after the live check): "Sign-in not ready" showed its message twice (the page text and the same words again in red). It now shows the page text once; any other reason (old browser, unreadable file) replaces it. `one-login.mjs` checks the message appears once on all three tools. `tests/e2e/review.mjs` no longer types the password again after a same-tab reload (the one login keeps the tab signed in); `run.mjs` accepts any tag on the newest What's new card.

## [1.2.0] - 2026-11-15

- One login for the Builder, KPI admin and Automation Review admin (`page/lfmp-login.js` + `page/lfmp-login.css`, byte-identical copies in leadpro-kpi `admin/` and automation-review `admin/`). With `page/lfmp-lock.json` (written by leadpro-kpi `scripts/set-shared-password.mjs`, same file in all three) the page shows the shared split-screen sign-in instead of its own lock. PBKDF2-SHA256 210,000 iterations as before; the password is never stored. The unlocked key (never the password) is kept in sessionStorage `lfmp-session` for the tab: switching tools in the same tab never asks again; it ends on Lock (any tool, and every other tab via `lfmp-lock-at`), 30 minutes without activity, or closing the tab. Without `lfmp-lock.json` the old `lock.json` lock runs unchanged.
- The GitHub token moves into the shared encrypted vault (localStorage `lfmp-vault`, AES-GCM with the shared key, also holding the Automation Review admin key). Connect once for the Builder and the KPI admin; the token help now asks for both repos (Actions, Contents, Secrets read/write; Variables read). Forget token clears it for both. The old `sab-gh-token` is dropped when the vault gets a token.
- Wrong-password limit: 5 wrong in a row pauses sign-in for 2 minutes in every tool and tab, with a live countdown; Forgot password? still works. Only a count and an end time are kept (`lfmp-login-guard`).
- Top bar: KPI admin and Review open in the same tab (no new tab, no ↗), also in the phone bar; Review now goes to the new Review admin (`/automation-review/admin/`).
- Tool colour: 4px band across the top, a BUILDER chip next to the LFMP mark, the menu underline and the headline eyebrow + accent use the tool colour (Builder gold `#d9a64e` / light `#a8741f`; text in light mode `#8a5d15` for AA). Phones hide the last-refresh line to make room for the chip.
- Fix: locking while the list was still loading showed "Couldn't unlock: …" on the lock screen.
- Tests: `tests/e2e/one-login.mjs` (47 checks across the three tools on one local site: sign in once and move both ways, Back, reload, Lock everywhere incl. another tab, 30-minute idle, wrong password, 5 wrong → countdown survives reload and other tools, Forget token, client pages never prompt or read the vault, colours + AA at 1440/390 light/dark, the old lock without `lfmp-lock.json`).
